# RM-2026-005 — Platform ownership, installation and GitHub updates

## Overview

### Goal, sequence and release

Deliver Runa as a ready library/foundation for customer business applications. Separate owner-only platform maintenance/install/update tooling from customer application Artisan tools, migrations, seeders, tests and deployment. Reuse the functioning development and production toolchain, with owner-operated GitHub installation/updates and customer-repository application deployment.

Activated by the owner on 2026-10-20. Its successor [RM-2026-006](../draft/RM-2026-006-module-framework.md) cannot begin until this roadmap is closed, merged and released.

Planned **0.3.0**, based on actual 0.2.1 after RM-004 and RM-007. Although architectural cleanup is substantial, install/update/integrity/identity are new features: `release_type: feature` increments minor under existing release rules. The platform remains pre-1.0 and this does not authorize a major bump. Document compatibility changes instead of declaring stable 1.0. Rebase the planned arithmetic on actual VERSION at activation without rewriting historical releases.

Standalone Runa seeders are selectable manually by owner tools. Installer runs initial platform migrations and explicitly required platform seeders once; updater executes required platform changes for the selected transition, recording successful steps so repeats/resume do not blindly rerun seeds. Remove the first-production flag and command, its validation and current-state documentation/agent guidance dependencies. Do not replace it with an installer flag. An existing applied migration cannot be assumed to rerun because its source changed: update fixtures must prove actual old-to-new schema/data correctness. The removal does not authorize resetting customer data. If a release transition cannot be implemented safely under the agreed model, return to discussion rather than silently invent a migration policy or schema-diff subsystem.

Separate Pest/PHPUnit, Vitest and Playwright application/platform roots and entrypoints. Customer test tooling targets their business application, not the Runa fixture browser harness. Exclude platform tests/maintainer harnesses from delivery while retaining useful app scaffolding, browser support and reporting.
