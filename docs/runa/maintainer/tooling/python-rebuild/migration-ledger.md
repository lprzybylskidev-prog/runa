## Current architecture

- `tools/core` owns immutable workspace/release/process/Compose contexts, the
  canonical process runner, safe state/locks, reporting, literal environment
  parsing, dependency composition and fixed delivery exclusions. It imports only
  stdlib/core. Runtime and cold host paths require no pip/project installation.
- `tools/application` composes guarded development/setup, registry/host plans and
  transport, deployment/installation, production validation, shared quality,
  scanners/hooks and development-only knowledge services. Fixed CLI modules use
  qualified imports and explicit dependencies; deleted runtime/executor/domain
  facades have no internal consumers. Process adapters preserve text/bytes and
  native exit/stdio/environment policies through the shared runner.
- `tools/application/testing` owns aggregate backend/frontend/tooling selection,
  lifecycle/reporting, worker cleanup and customer support. Native PHP/JS engines
  remain. Customer tests/configuration/frozen inputs belong under `src/app`.
  Root package metadata ships shared frozen developer tools and explicit resources;
  private suites/policy are absent from customer artifacts and production images.
- `tools/maintainer` supplies private composition, release/history/quality policy,
  suite selection, localization and native acceptance. Private fakes/workspace
  factories live under `tests/python/support`; suites do not import each other.
  Owner Ruff/Pyright settings extend shared strict rules without scope exclusions.
- `distribution` independently acquires verified releases, initializes customer
  repositories and plans/applies/resumes development updates. External/core source
  bundles, wheels and the standalone first-acquisition file have explicit metadata.
  Initial acquisition remains independently stdlib-only; later runtime operations
  use injected core processes and the version-separated protocol-1 gateway.

Every authored function/fixture/adapter signature declares inputs/results.
Typed consumed-field decoders cover host frames, command/quality catalogs,
receipts, deployment/install/update journals and knowledge provider/store records.
Extra evidence and supported legacy omissions retain their established behavior.
Full strict Pyright PASS is established only by final verification, together with
format/lint, package builds, suites, live acceptance and security/AI gates.

## Callers and resources

PHP Actions, Compose startup, Git hooks and quality definitions select fixed
package modules or the existing supported transports. Module generation selects
an explicit backend scope before native arguments. Bin aliases preserve all 37
baseline symlink targets. Customer/owner aggregate defaults cover backend,
frontend and tooling; focused scopes keep their native ownership and exits.
VS Code uses the frozen container interpreter/Ruff with strict Pylance. Public
commands, Python/tool setup, editor/development and production guides describe
that same workflow. Package resource lists include locks/configuration, YAML/
JSON metadata and required PHP helpers; no undeclared source package or obsolete
shell resource is retained. Builds, wheels and customer/production acceptance
remain final gates rather than implementation evidence.

Native acceptance resolves protected services from the actual checkout and model
cache from its configured embeddings service. It never assumes `runa-dev`, copies
an owner collection or removes the shared cache. Disposable fixture projects keep
their explicit identities, operation journals and scoped cleanup. SMTP/FastCGI/
PostgreSQL fixtures have typed transport/protocol boundaries without starting
infrastructure when imported.

## Retained boundaries and retirements

Retained bin/hook/owner/external launchers are thin fixed-purpose process
transports. Boost keeps process cwd/exec for stdio; daemon recovery recognizes
only exact previous-release owned process identities. Cross-version installation,
PHP/JS/Docker probes and isolated refusal fixtures retain real process boundaries;
none authorizes script-as-library loading, import-path injection, global workspace
mutation or a parallel operational process/state implementation.

The obsolete executor package, compatibility facades, filename suite runners,
runpy/dynamic import wiring, imported-function replacement and owner exception
callbacks are removed. The unused Docker inventory, one-time PostgreSQL switch
and PHP Alpine shell simulation are retired; their meaningful current lifecycle,
collation and full production/security scenarios remain. Exact historical hashes
and dated evidence stay immutable. The temporary corrected PostgreSQL derivative
remains governed by its existing removal condition; this roadmap adds no security
exception or dependency.
