# Owner procedure and historical evidence

Source classification: `docs/runa/handbook/architecture/configuration.md`. These owner-only procedures and dated execution records are retained separately from customer guidance. Historical claims keep their original context; current public operations are documented in the handbook.

Private `.env`, `.env.testing` and production environment files remain at repository root. Bootstrap loads that environment path explicitly. File disks separate application/platform private/public ownership; the default local disk resolves to application-private storage. Cache consumers use the application file store or explicit platform runa_file store. Full composition details belong to [Application Architecture](../../maintainer/architecture/application-architecture.md#delivered-source-and-runtime-composition).

Canonical ID/name/version/compatibility and optional public logo metadata live in customer-owned `src/app/application.json`, not `.env` or branding config overrides. Platform metadata lives separately in `src/runa/platform.json`; its version must match canonical root VERSION. The bundled customer app is a Runa placeholder at version 0.0.0. Protected branding config validates and projects the manifest for runtime/build consumers; customer config may customize mail/footer presentation but identity-key overrides are rejected. See [application identity and compatibility](../../maintainer/architecture/application-architecture.md#application-identity-and-compatibility) for the schema and supported range grammar. No database settings or module registry is introduced.
