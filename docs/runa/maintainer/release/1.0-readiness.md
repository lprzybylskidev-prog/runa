# Runa platform 1.0 readiness

The [public release readiness guide](../../handbook/release/1.0-readiness.md)
owns the shared requirements: representative data, query/index review,
use-case-specific performance, production-like runtime, security review,
deployment/recovery and subsequent stable-update regression planning. Apply all
of those requirements when preparing platform 1.0.0 or a later stable platform
update; this owner entrypoint adds the platform verification scope below rather
than maintaining another copy of the shared checklist.

## Platform verification and release authority

Before platform 1.0.0, run the supported complete owner graph with `--all`, in
addition to the release-scale scenarios established by its accepted readiness
roadmap. Preview the exact graph and retain complete all-group results and native
evidence under the [owner quality contract](../quality/README.md#manual-group-selection).
A scoped result cannot satisfy this requirement. Resolve failures through the
normal [roadmap fix-point workflow](../workflows/roadmaps.md#final-verification-point).
The existing owner backend SIGSEGV disposition remains governed by its
[canonical acceptance procedure](../testing/strategy.md#backend-sigsegv-owner-acceptance).

Passing verification does not authorize promotion to 1.0.0: only the owner decides
that Runa is ready. Later stable updates retain release-scale regression/load and
query/index review using the established dataset and critical scenarios. Optional
performance dependencies still need explicit approval. Follow the
[release workflow](../workflows/releases.md) for version finalization and publication.
