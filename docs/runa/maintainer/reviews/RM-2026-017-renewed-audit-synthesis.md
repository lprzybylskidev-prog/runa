### RA-01 source-backed refinement

The earlier renewed query observation is retained: four admitted HTTP-kernel GETs
returned 200 with 479/131/112/581 queries. SQL templates, without bindings, are
stored in `query-observations.json`. They are not FPM latency measurements and do
not establish row-dependent N+1.

ModuleRegistry invalidates its cached snapshot before a new root transaction and
on non-plain-SELECT SQL. ModuleSettings::reading opens a transaction per scalar
read; currentValues caches against the locked RegistrySnapshot object. Consequently
independent scalar reads can repeatedly enter a fresh root and reload the registry.
AccountPolicy/LookupIdentity/CredentialPolicy/PolicyExceptions also repeat current
identity, restriction and settings reads across nested admission/declaration paths.
OperationGuard::assertCurrent and ModuleAvailability deliberately recheck fences.

Repair must batch owning current inputs or reuse an explicitly locked read scope;
it must not remove freshness checks to meet a query target. Preserve same-connection
writes, rollback/reconnect, health expiry, revocation and reused-worker behavior.
Existing ModuleRegistryCacheTest explicitly protects locked read reuse and
same-connection invalidation. Add analogous supplied-read-path coverage and compare
SQL template counts, not an arbitrary absolute HTTP query ceiling. The precise
scope/lifetime design remains a required point-5 pre-code design check. No new
long-lived cache or architecture replacement is approved by this report.

Other backend review boundaries retain their actual inspected owners: native
ModuleTransactions and Auth/Permissions participants, Admin aggregate transport,
Audit append/refusal paths, startup/maintenance/worker state, logging, images,
mail and minimal App/reference integration. Existing tests and the old report
support review navigation, not blanket backend correctness. No demonstrated new
security exploit, transactional corruption or missing business module is asserted.
