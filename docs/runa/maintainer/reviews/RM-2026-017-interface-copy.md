Point 10f, 2026-11-07. This review applies the existing
[interface copy standard](../../handbook/design/visual-direction.md#interface-copy-and-preference-controls).

## Inventory and evidence boundary

Inspected the shared locale catalogue and Auth welcome/entry/account families,
Admin dashboard/module/settings/resource/form presentation, Permissions source
management declarations, Audit history presentation, reference workspace copy,
shared feedback/field defaults, HTTP error catalogue and Auth mail bodies/layout.
The table below records actual text candidates and their presentation owners,
including retained descriptions whose purpose goes beyond a heading or label.
Data-owned names, setting descriptions and recorded Audit values remain data.

A bounded real Nginx observation at `http://nginx:8080` found HTTP 503 at `/`,
`/auth/login`, `/auth/register`, `/auth/forgot-password` and an unknown route.
The rendered maintenance shell correctly showed its title, retry guidance and
request identifier. Login could not reach a username control, so account/Admin
observations were not reached. Evidence is preserved under
`.runtime/artifacts/playwright/RM-2026-017-point10f/observations.json` and adjacent
screenshots. These are observations of the maintenance shell, not the SPA or
new copy. No guard, maintenance state, module installation or stored data was
changed to bypass this condition. Current runtime/assets preparation belongs to
10i; the current acceptance sheet continues to withhold readiness.

The supported focused frontend runner rendered current Auth components in
Chromium in both locales. The new diagnostic verifies the absence of the login
paragraph while retaining username input, required-field validation without a
write, and the recovery explanation/email input. Other entries below are
source-verified dispositions; prior screenshots are historical context, not
current-source acceptance. Full affected browser coverage remains point 12 and
owner acceptance remains point 11.

## Contracts, versions and instruction products

The public entry controller retains its `description: ComputedRef<string>` and
presentation replacements; an empty description is an existing supported state.
Only the unused login catalogue entries disappear. No API/schema/signature,
capability, dependency or permission changes. Auth remains the already unreleased
6.0.0 candidate; this compatible copy correction belongs to that candidate rather
than a second artificial version. Framework API and other module candidates are
unchanged. Platform VERSION remains 0.7.0 with the approved 0.8.0 projection.

The public entry guide documents the actual default. Owner/customer frontend
skills already select the canonical copy standard, and both AGENTS products
already require localization, usable defaults and preservation of security
instructions. No new rule, duplicate procedure or customer protected-source
permission is needed. Customer authoring templates were read as product data.
