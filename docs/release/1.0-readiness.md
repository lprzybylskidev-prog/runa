# Release 1.0 Readiness

This document is intentionally high-level. It defines what must be proven before the user chooses to promote Runa from development major version `0` to first ready major version `1`.

The exact testing/optimization implementation belongs to the roadmap preparing 1.0.

## Data scale

Seed important tables with large, realistic datasets.

Do not optimize against only tiny development fixtures.

Representative data should include realistic:
- relation density,
- state/status distributions,
- selective and non-selective filters,
- historical/current record mix,
- text lengths and optional fields.

## Query review

Identify representative high-value/heavy queries.

For those paths:
- benchmark,
- inspect query count/N+1 behavior,
- use PostgreSQL `EXPLAIN (ANALYZE, BUFFERS)` where appropriate/safe,
- review index usefulness/overlap,
- validate pagination/search behavior at scale.

## Application performance

Run production-like load/performance tests for meaningful critical flows.

Do not set one artificial latency number for every endpoint. Define acceptable behavior by use case.

Inspect:
- backend throughput/latency,
- queue behavior,
- frontend bundle/render behavior,
- database resource use,
- memory/process behavior.

## Production-like runtime

Perform release validation in a production-like stack:
- production images,
- Nginx/PHP-FPM,
- PostgreSQL,
- worker,
- scheduler,
- production configuration/caches,
- storage,
- health checks.

Verify the production build contains no development AI/RAG stack.

## Security review

Perform a deliberate security review of the current attack surface.

Include:
- dependency/container vulnerability state,
- secrets/config,
- auth/authz boundaries implemented by then,
- input/output handling,
- browser security headers,
- sensitive data/logging,
- file/integration surfaces implemented by then,
- production privilege/exposure.

Resolve or explicitly disposition findings before 1.0.

## Backup and restore

Create and verify a realistic backup.

Perform a restore into a safe isolated target.

Run application smoke checks against restored data/storage.

## Deployment and rollback

Exercise:
- clean production installation,
- normal upgrade deploy,
- production seeders,
- health checks,
- rollback behavior,
- migration compatibility constraints.

## Full release gate

Run the complete applicable final quality gate with all relevant impact areas.

Resolve failures using the normal roadmap fix-point process.

## User decision

Passing readiness does not automatically change the major version.

Only the user decides that Runa is ready for `1.0.0`.

## Subsequent stable updates

After 1.0, include release-scale regression/load and database query/index review in update planning, using the established representative dataset and scenarios. Scope the work to changed and critical paths while retaining a meaningful baseline; do not skip scale validation merely because tiny fixtures pass. The 1.0 roadmap establishes concrete datasets, tools and acceptance criteria. This document does not pre-approve optional performance tooling dependencies.
