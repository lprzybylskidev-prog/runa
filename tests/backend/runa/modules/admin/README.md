# Admin foundation tests

EntryTest prepares real target-platform Core installation, session login, ordinary
direct grants, password proof and guarded bootstrap. It authors expiry, foreign
proof/session/security-version, revocation, maintenance/Core failure and safe
diagnostic projection cases. Source/runtime declarations and explicit initial
update history are covered without claiming native installer or rendered acceptance.

During pre-release development, this fixture selects the specified 0.7.0 runtime
for availability/update planning without changing platform VERSION or source data.
Use the supported owner backend runner with explicit module path or native name
filter and a disposable worker. The common fixture removes exact Admin registration
and update history before removing its Core prerequisites. No Admin tables exist.
Complete suites/browser/native installation/update acceptance remain final-only.

ProjectionTest authors independent App bootstrap/ownership/freeze cases, authorized
field/value/control projection, read-only/unknown writes, filter/sort/options
refusals, raw-secret and handler-error redaction, bounded DTOs and registry
changes before/after owning reads. It uses source-owned temporary App classes and
an explicit authorizer double to isolate projection from the real session/proof
entry cases in EntryTest. Those doubles do not establish native grant acceptance.

Native transaction cases in EntryTest use the target runtime and real session,
password/factor enrollment and single-use proof. They author Auth-first joined
commit, Audit rollback, stale review, duplicate writer/proof refusal and standalone
API 2.0.0 consumption. ModuleHealthTest covers exact-operation admission without
external work inside a transaction, expiry/source changes and scope disposal.
Complete area/concurrency/native acceptance remains final-only.

Independent command coverage uses the native target runtime/session/proof and
temporary App-owned source handlers. It verifies pre-validation admission,
allowlisted input/review/destructive confirmation, safe errors and result
projection, stale revision refusal and execution outside the entry transaction.
The fixture writer is transport evidence, not a replacement for owning Core
business/Audit cases. Native aggregate execution is delivered in point 6.

Point-7 Auth administration cases author bounded directory/cursor/login disclosure,
deleted/profile/address grants, every lifecycle intent, create/invite/secondary/
preference workflows, stronger-proof denial/success/reuse, policy preview/publish/
restore/history, session/trust scoping, selected/all bulk reviews and read-only
command denial. Frontend cases exercise shared subject selection, collection
read-lane cancellation and public default composition; browser scenarios retain
final-only light/dark and responsive acceptance. Focused results are recorded in
the active roadmap; this inventory does not claim suite PASS.

Point-8 cases author native custom-role creation/edit/delete and stale reviews,
required Audit/proof rollback, add/replace/copy/from-user preset semantics,
source/system readonly denial, dedicated protected authority/self-escalation/last
administrator and confirmed force deletion. Audit viewer cases separate cursor
summaries from redacted detail, exact entity filters, unknown references and current
grant revocation. Frontend cases author dirty record selection, immutable/source
presentation, effective-account cursor fencing and escaped entity history links.
Built default E2E scenarios cover desktop/tablet/mobile light/dark in final verification.

Point-9 operational fixtures author exact-grant and maintenance refusal, bounded
cached diagnostics, safe settings/set-state, generation staleness, actor-bound
Optional review, reservation/publication/compensation Audit failure and cooperative
cancellation rollback/idempotency/privacy. Disposable module sources/queue rows are
owned and removed by OperationalModule. Frontend scenarios cover delayed account
responses, no replay, frozen destructive input, denied controls and retained secret
drafts after conflict; responsive/theme browser scenarios remain final acceptance.
