# Runa Agent Skills

Local skills are adapted project guidance, not upstream mirrors.

Load only the skill relevant to the current work. Each `SKILL.md` routes to detailed `references/` files.

Authority:

1. active roadmap,
2. current code,
3. `AGENTS.md`,
4. local skills/docs,
5. generic/upstream guidance.

Never let an upstream skill override Runa policy.

Each skill includes `SOURCE.md` with pinned research provenance and local adaptation notes.

## Documentation and knowledge ownership

The root AGENTS contract and docs/README.md define the durable placement rule. Every domain skill applies it when changing a rule/procedure: application-specific records go to docs/app, customer-facing Runa guidance goes to docs/runa/handbook, and owner platform maintenance/history goes to docs/runa/maintainer. The presence of development, testing, AI or security content does not make a guide owner-only. Supplied skills and public workflows remain usable after the maintainer directory is removed. Avoid customer links/commands that depend on excluded files, never recreate src/app/docs, and keep one authoritative guide for each rule.

Update existing relevant skill/pattern references with the implementation. Preserve closed-roadmap/dated-evidence bytes, validate public links and application lifecycle roots, then refresh staged allowlisted knowledge. Customer receipts prevent private maintainer sources from entering that corpus. No new task-specific skill or parallel policy store is needed.
