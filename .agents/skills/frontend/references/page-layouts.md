# Page Patterns

Bundled MinimalLayout and ApplicationLayout pages share `/favicon.ico`, declared once in the root/review HTML entry heads. Native/static errors declare the same icon in their PHP document wrapper. Keep document metadata at the HTML entry level rather than duplicating head mutations in layout components. External consumers supply their own document head and icon asset; importing a layout does not mutate their favicon.

## Minimal layout

Canonical source: `resources/js/layouts/MinimalLayout.vue`, public import `MinimalLayout` from `@/runa/ui`. AuthLayout was removed at the owner's request during RM-2026-004 point 2.

Owns the accepted backdrop, default identity header, cycling language/theme controls, skip link/focusable main and configurable footer. Optional named slots: header, content, illustration, actions, footer. Content falls back to the default slot; slots expose translator `t`. The supplied Runa illustration is built in and visible by default; content occupies the left panel, the illustration the right at `lg`, with a compact 240px illustration above content on narrow screens. Set `illustration: false` explicitly for one column, or override the illustration slot. Actions follow content. Footer stays in normal flow at the viewport bottom on short pages and after long content. `footer.visible: false` hides even a custom footer slot.

The layout owns locale/theme composables once. Consumers use scoped `t`, preserving existing browser keys, cover timing, inert content and focus restoration. Identity overrides are scoped with `IdentityProvider`; no global installation is required. Custom headers replace the default brand and preferences together.

## Preserved root welcome view

`resources/js/App.vue` consumes MinimalLayout directly with only the existing heading/description as content. The layout itself supplies `AppBrandIllustration.vue` by default. Illustration, geometry, backdrop and preference interactions are preserved. The footer now includes independent application/platform versions. No authentication behavior exists. The original root was accepted on 2026-10-18; the point-2 layout/footer and subsequent mobile corrections were accepted on 2026-10-18.

## Application layout

Canonical source: `resources/js/layouts/ApplicationLayout.vue`, public `ApplicationLayout` from `@/runa/ui`. Point 3 was visually accepted by the owner on 2026-10-18. No business/admin modules or authentication are implemented.

Supply typed navigation/topNavigation descriptors, URL-derived current context, title/description, independent sidebar/topbar visibility and contained/fluid width. The sidebar stays fixed at desktop widths, scrolls independently and persists collapse/groups by application identity. Below 64rem it becomes a focus-trapped, Escape/backdrop-dismissable drawer with focus return; it never relocates to another side. The top header stays visible with sticky positioning; toolbar scrolls with the page. The brand row and header are both 64px high, the Runa mark sits in the same 42px square as MinimalLayout, and sidebar collapse/expand is a 36px sm control before top navigation, inset 8px from the header left edge. Sidebar groups are full-width disclosure buttons with a centered chevron inside; their parent label does not navigate. Collapsed enabled/disabled icons share exact centering; the sidebar footer retains just the platform version. Dotted left/right edge indicators fade in when more top-navigation content is available in that direction and disappear at its ends or when it fits. The header is 64px high; its horizontal navigation scrollbar sits at the bottom edge. Wheel input over overflowing top navigation is consumed for horizontal movement (also at the ends), leaving Ctrl+wheel zoom native. Top-navigation dropdowns are floating cards teleported outside the nav scroller; they overlay content without stretching the 64px header. Sidebar groups expand inline. Escape/outside click/document scroll/resize dismiss cards; nav scrolling repositions the open card, and Tab boundaries preserve navigation focus order. The circular initials disclosure is a slot seam, not authentication functionality.

Workspace slots follow heading/actions → breadcrumbs → statistics → toolbar → content/default + optional supplementary region. Other slots: sidebar-bottom, user-menu and footer. All expose t; sidebar-bottom exposes collapsed. Footer/identity and extracted preference controls are shared with MinimalLayout. Both layouts use the finalized Tooltip via AppPreferenceControls; ApplicationLayout uses sm language/theme controls and retains its unique circular initials trigger and delegates its existing user-menu content to Popover. `topbar: false` hides the area navigation/avatar while retaining utility controls and access to a visible sidebar. Print hides navigation/footer/unnecessary controls by default and may be explicitly overridden.

Use `usePageResolver` with exact paths and matching named server entries; never store active selection as a preference. In the temporary application review, `/__review/application/{overview,projects,activity,archive,team}` are separately registered, named local/testing paths. Unknown paths remain real 404s and all review registrations are absent in production. Production applications must provide their own named entry paths. No routing dependency is installed.

## Temporary UI review skeleton

`resources/review/ReviewCatalog.vue` is a separate, development/testing-only entry at named route `review.ui` (`/__review/ui`). It reuses MinimalLayout and public UI imports; the controls category (`resources/review/ReviewControls.vue`) now exposes all button variants/tones, sizes, icon-only/busy/disabled/toggle states, and joined button groups. Icon-only buttons demonstrate icons in context; no separate icon or avatar showcase is included. Interactive state switches and output counters support manual testing. The feedback category (`?category=feedback`, ReviewFeedback.vue) adds inline alert tones/dismissal/actions, badge sizes/statuses, toast controls with a persistent inline error, tooltip hover/focus and a simple informational popover. The catalog uses the one-column MinimalLayout; the separate minimal preview retains its illustration. Categories awaiting implementation say so; ApplicationLayout has its separate synthetic review entry; email has the native preview at `/__review/email`. Build via `vite.review.config.mjs`, never the production entry. This temporary pattern is retired in RM-2026-004 point 21; do not make application tests depend on it after retirement.

Minimal review: `/__review/ui?preview=minimal` scopes Atlas identity, independent application version and actual platform VERSION. Controls exercise short/long content, optional illustration and footer visibility. All web previews retain PL/EN and light/dark preference controls. This is temporary review content, not a shipping application.

Application review: `/__review/application/overview`. Synthetic modules/areas and preview-only controls exercise navigation, optional workspace regions, contained/fluid width and long-content scrolling. Reuse the existing four licensed Tabler icons; the final buttons/layers/containers/KPIs are integrated at their owning later roadmap points.

Application navigation review includes the menu-specific link variants, sidebar/top navigation, footer and initials disclosure. Synthetic breadcrumbs/statistics/content are composition fixtures until their owning component points. Shared thin violet scrollbars style both navigation scroll axes in light/dark; native scrolling stays intact and forced-colors uses system defaults. The application preview's Long menus toggle adds/removes synthetic overflow links that reuse known review pages.

## Email layout

Native Laravel Markdown/non-Auth notification default: `config/mail.php`, `resources/views/mail/{html,text}` and overridable `runa-mail` namespace. See `docs/architecture/frontend.md` (Native email layout) for body/header/actions/footer/text/CID contracts. Use shared `resources/css/light-palette.css` tokens, table layout, light theme and system monospace fallbacks; do not import Vue into mail. Branding is configured in `config/branding.php` with separate application/platform versions. Temporary review: `/__review/email?locale=pl|en`, `format=text|eml`, `long=1`, `images=blocked|public`; array transport only. Browser screenshots do not prove Outlook/Gmail/Apple Mail compatibility.

## HTTP errors

Use **MinimalLayout.vue directly**, with error-specific content in its normal slot; it is also the welcome-dashboard template and the future Auth template. Do not create an error-only shell/card/background/header/footer. `resources/errors/render.mjs` builds native HTML from this exact component, its shared backdrop/illustration/footer and existing controls. `staticPreferences` renders native GET navigation without browser/storage hooks; ordinary interactive consumers are unchanged. `resources/views/errors/page.php` only wraps/selects/escapes generated private shells for native Laravel errors and the static 503 finalizer. No Node/Vue/JS runtime is needed by the resulting pages. `docs/architecture/frontend.md` owns generation/copy/locale/theme contracts; the generated files and standalone assets are ignored build output. Error-specific content does not duplicate shell markup or CSS.
